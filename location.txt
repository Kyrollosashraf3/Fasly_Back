================================================================================
تسليم الفرونت إند — اللوكيشن + خريطة افتقاد المنازل
================================================================================

تصحيحات مهمة قبل القراءة:
--------------------------------------------------------------------------------
1. مفيش جدول لوكيشن جديد. الإحداثيات بتتخزن في نفس جدول boys في العمودين
   الموجودين أصلاً:
       boys.latitude   float | null
       boys.longitude  float | null
   يعني الـ GET العادي /boys و /boys/{id} يرجّعوا اللوكيشن ضمن بيانات الولد.
2. مفيش enum جديد للوكيشن. "نوع الافتقاد" هو الـ FollowEnum الموجود أصلاً
   والمخزّن في follow_ups.status:
       call | visit | whatsapp | no_answer | other
   لو الباك استلم status مع تسجيل اللوكيشن، بيكتب سطر افتقاد في follow_ups
   في نفس العملية. لو الـ status اتبعت null/متتبعتش، بتتسجل الإحداثيات بس.
3. مفيش has_whatsapp. أي ولد له رقم هاتف هيطلع له رابط واتساب (wa.me) ورابط
   تليفون (tel:) في بيانات الخريطة.
4. كل الميزات الجديدة تحت prefix واحد: /locations  +  توكن Bearer إلزامي.
5. Swagger جاهز على /docs و /openapi.json.

================================================================================
التاسك 1 — زرار "تسجيل اللوكيشن الحالي" جوّه بيانات الولد
================================================================================

الفكرة:
- الخادم / الأمين / أي مستخدم له صلاحية يشوف الولد، يروح يقف قدام بيت الولد،
  يضغط الزرار، المتصفح يقرأ الـ GPS الحالي ويرسله للباك، الباك يكتبه على
  boys.latitude / boys.longitude.
- مستقبلاً الولد نفسه يعمل لوجين بحسابه (role=user) ويضغط نفس الزرار؛ فيه
  route خاص بيه بيكتب إحداثياته هو بس.

--------------------------------------------------------------------------------
1.1) POST /locations/boys/{boy_id}     (تسجيل لوكيشن ولد معيّن)
--------------------------------------------------------------------------------
Headers: Authorization: Bearer <access_token>
Body (JSON):
{
  "latitude": 30.0501,          // required, -90..90
  "longitude": 31.2004,         // required, -180..180
  "status": "visit",            // optional: call|visit|whatsapp|no_answer|other
  "note": "زيارة البيت"          // optional, يروح لـ follow_ups.note لو status اتبعت
}

Response 201:
{
  "boy_id": 12,
  "boy_name": "مينا",
  "latitude": 30.0501,
  "longitude": 31.2004,
  "updated_at": "2026-11-17T10:22:31.123456Z",
  "follow_up_id": 88            // null لو مفيش status اتبعت
}

السلوك:
- بيحدّث boys.latitude / boys.longitude (ودي هي النقطة اللي الخريطة هترسمها).
- لو status اتبعت: بينشئ FollowUp(boy_id, teacher_id, class_id snapshot,
  action_date=اليوم, status, note, recorded_by=المستخدم الحالي) في نفس
  Transaction. لو مفيش خادم مرتبط بالولد (Group) والـ caller مش خادم، هيرجع 400.
- لا يلمس boys.last_visit_date — ده تاريخ زيارة أبونا للاعتراف، مش زيارة الخادم.

الصلاحيات:
- super_admin / general_admin / admin / teacher: يقدروا يسجلوا لأي ولد داخل
  نطاقهم (الخادم: فصله؛ الأمين: فصله/فصوله؛ العام: كل حاجة).
- user (الولد): يقدر يسجل لنفسه بس عبر 1.2، ولو بعت status هنا هيتم تجاهله (ما بيكتبش
  follow-up لأن الولد مسموحلهش يكتب افتقادات).

--------------------------------------------------------------------------------
1.2) POST /locations/boys/me        (الولد يسجّل لوكيشن بيته بنفسه)
--------------------------------------------------------------------------------
نفس الـ body حق 1.1 (الـ status متجاهَل تماماً هنا).
يستخدم user.boy_id من التوكن — مفيش boy_id في الـ path.
Response 201 بنفس شكل 1.1 بـ follow_up_id = null.
لو المستخدم مش role=user → 403.

--------------------------------------------------------------------------------
1.3) GET /locations/boys/{boy_id}/current
--------------------------------------------------------------------------------
Response 200: نفس شكل 1.1، أو null لو الولد لسه مالوش إحداثيات.
يستخدمه الفرونت لما يفتح صفحة الولد: لو null يظهر الزرار بحالة "سجّل الموقع".

الأخطاء:
401 توكن مفقود/منتهي | 403 خارج النطاق | 404 ولد غير موجود |
422 إحداثيات غلط (خارج النطاق) | 400 مفيش خادم عشان تسجيل الافتقاد.

--------------------------------------------------------------------------------
1.4) كود مقترح للزرار في الفرونت
--------------------------------------------------------------------------------
async function saveCurrentLocation(boyId, { alsoLogVisit = false } = {}) {
  const pos = await new Promise((resolve, reject) => {
    if (!navigator.geolocation)
      return reject(new Error('Geolocation not supported'));
    navigator.geolocation.getCurrentPosition(resolve, reject, {
      enableHighAccuracy: true,   // مهم لأننا واقفين قدام البيت
      timeout: 10000,
      maximumAge: 0,              // لازم قراءة جديدة مش كاش قديمة
    });
  });

  return api.post(`/locations/boys/${boyId}`, {
    latitude: pos.coords.latitude,
    longitude: pos.coords.longitude,
    status: alsoLogVisit ? 'visit' : undefined,
  });
}

حالات لازم تظهر للمستخدم:
- PERMISSION_DENIED → "السماح باللوكيشن مغلق من إعدادات المتصفح".
- POSITION_UNAVAILABLE / TIMEOUT → "تعذّر قراءة اللوكيشن، حاول تاني".
- 404 / 403 → كما هو موضح فوق.
- بعد النجاح: اعمل invalidate لـ /boys/{id} و /locations/map عشان الماركر يتحدّث.
- التنبيه: المتصفحات تسمح بـ geolocation على HTTPS أو localhost بس.

--------------------------------------------------------------------------------
2.1) GET /locations/map  — كل حاجة في طلب واحد
--------------------------------------------------------------------------------
Query params (كلها اختيارية):
  latitude=30.049      // موقع "أنا"/الخادم الآن. لو اتبعت بيعملوا نقطة البداية
  longitude=31.199     // لو اتتركوا، الباك يبدأ من أول بيت ويرجّع origin.source=first_house
  scope=group|class|all     // الافتراضي class
        group = مجموعتي فقط (Servant group)
        class = الفصل كله (أو كل فصول الأمين/الأمين العام)

  class_id=3           // تضييق إضافي على فصل واحد جوّه النطاق

--------------------------------------------------------------------------------
2.2) إزاي تستخدم الـ response في الرسم
--------------------------------------------------------------------------------
1) استخدم Leaflet + بلاط OpenStreetMap المجاني (مفيش API key):
   L.tileLayer('https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png', ...)
2) ارسم "أنا" من origin (marker مختلف / دائرة زرقاء).
3) ارسم LineString من polyline مباشرة — الباك رتّب البيوت أقرب فأقرب بالفعل،
   متعملش nearest-neighbour تاني في الفرونت.
4) لكل house في houses:
   - Marker فوق boys.latitude/longitude باسم الولد.
   - فوق الماركر: أيقونة واتساب → window.open(whatsapp_url)
     وأيقونة تليفون → window.location.href = call_url
     وأيقونة (+) → تفتح بانل المتابعة.
   - البانل يتحول منه prefill مباشرة: boy_id و teacher_id و status=visit
     و action_date كلهم محطوطين؛ المستخدم يعدّل status/note بس، وبعدين
     POST /follow-ups بالجسم ده (الباك هيضيف class_id بنفسه).
5) leg.order و leg.distance_m و leg.walk_minutes للـ labels على الخطوط.
6) houses مرتبة زي ordered_boy_ids بالظبط — استخدمها لترقيم البيوت 1،2،3...
7) unlocated: ظهرهم في قائمة جانبية أو ماركرات رمادية بـ CTA "سجّل اللوكيشن"
   تستدعي التاسك 1 لكل ولد. لو اتبعت latitude/longitude للخريطة، اعمل refetch
   بعد التسجيل عشان البيت ينقل من unlocated لـ houses.
8) الفلاتر: 3 أزرار group / class / all تبعت scope. لو الأمين عايز يشوف
   مجموعة خادم معيّن ابعت teacher_id. لو super/عام عايز فصل واحد ابعت class_id.
9) origin.source == "first_house" يعني الخادم مبعتش إحداثياته — اطلب إذن GPS
   وابعته في الطلب التالي عشان الخط يبدأ من مكانه هو.

--------------------------------------------------------------------------------
2.3) القواعد والصلاحيات
--------------------------------------------------------------------------------
- super_admin: كل الفصول؛ general_admin: فصوله المسجّلة؛ admin: فصله؛
  teacher: فصله، و scope=group يبقى مجموعته هو؛ user: بيته هو بس.
- خارج النطاق بيرجع 403 أو 404 زي باقي الباك (مفيش تسريب لبيوت تانية).
- scope=group لمستخدم مش خادم ومفيش teacher_id → 400 برسالة واضحة.
- البيانات دي للقراءة فقط؛ أي تعديل بيحصل عبر التاسك 1 أو /follow-ups.
